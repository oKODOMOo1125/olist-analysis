## 2026-11-03 · ออเดอร์ช่วงท้ายของข้อมูลยังเห็นไม่ครบ (right-censoring)

- **เจออะไร:** อัตราออเดอร์ที่ส่งนานเกิน 100 วันเป็น 0% ในเดือน 2018-07 และ 2018-08 ขณะที่เดือนอื่นอยู่ที่ 0.01–0.47%
- **ทำไม:** วันที่สั่งซื้อล่าสุดในข้อมูลคือ [วันที่] ออเดอร์ที่ยังไม่ถึงมือลูกค้าเป็น NaN และหลุดออกจากตัวหาร เดือนท้าย ๆ จึงเหลือแต่ออเดอร์ที่ส่งเร็ว
- **หลักฐาน:** `notebooks/02_python.ipynb` เซลล์อัตรารายเดือน
- **ผลต่องาน:** ห้ามสรุปว่าช่วงท้ายส่งเร็วขึ้น ใช้เฉพาะออเดอร์ที่สั่งก่อน 2018-09-01 และระวังเดือนท้าย ๆ ในขอบเขตด้วย
- **ไปอยู่ที่:** README > Limitations

## 2026-11-03 · Olist ตั้งวันที่สัญญาส่งไว้เผื่อมาก

- **เจออะไร:** มัธยฐานของ `days_late` คือ −12 ออเดอร์ส่วนใหญ่ถึงก่อนวันที่สัญญาราว 12 วัน

- **ไปอยู่ที่:** README > Key findings

## 2026-11-03 · รีวิวเดียวผูกกับหลายออเดอร์

## 2026-11-12 · เวลาส่งของลูกค้าทั่วไป

- **เจออะไร:** มัธยฐาน 10.2 วัน (IQR 6.8–15.7, n = 96,204) และ 1 ใน 10 รอเกิน 23.1 วัน ส่วน mean 12.5 วัน สูงกว่า median เพราะหางขวายาว
- **ทำไม:** มีออเดอร์ส่งนานมากจำนวนหนึ่ง (ช่วงกว้างถึง 209 วัน) ดึง mean ขึ้น แต่ไม่ดึง median
- **หลักฐาน:** `notebooks/04_.ipynb` เซลล์ quantile
- **ผลต่องาน:** รายงานด้วย median + IQR + P90 (DECISIONS.md ข้อ 1)
- **ไปอยู่ที่:** README > Key findings

## 2026-11-12 · ออเดอร์ที่ช้าที่สุด 10% ได้ 1 ดาวมากกว่า 5 เท่า

- **เจออะไร:** ออเดอร์ที่ส่งนานเกิน P90 (23.1 วัน) ได้ 1 ดาว 37.1% (n = 9,556) เทียบกับ 6.7% ของที่เหลือ (n = 86,005) คะแนนเฉลี่ย 2.9 เทียบกับ 4.3
- **ทำไม:** ยังเป็นแค่ความสัมพันธ์ ไม่ได้พิสูจน์ว่าความช้าเป็นสาเหตุ (อาจมีปัจจัยอื่น เช่น รัฐปลายทาง หรือประเภทสินค้า)
- **หลักฐาน:** `notebooks/04_.ipynb` เซลล์ slow_10pct ใช้รีวิวล่าสุดของแต่ละออเดอร์ และ inner join จึงเหลือเฉพาะออเดอร์ที่มีรีวิว (n = 95,561)
- **ผลต่องาน:** เป็นข้อค้นพบหลักของรายงาน ต้องบอกข้อจำกัดว่ามาจากคนที่เลือกรีวิว (non-response)
- **ไปอยู่ที่:** README > Key findings

## 2026-11-16 · ลูกค้าแทบไม่กลับมาซื้อซ้ำ

- **เจออะไร:** ลูกค้า 96,096 คน (`customer_unique_id`) สั่ง 99,441 ออเดอร์ มีแค่ 2,997 คน (3.1%) ที่ซื้อตั้งแต่ 2 ครั้งขึ้นไป
- **ทำไม:** `customer_id` ถูกสร้างใหม่ทุกออเดอร์ ต้องนับคนด้วย `customer_unique_id` เท่านั้น
- **หลักฐาน:** `notebooks/05_eda.ipynb` ขั้น 2 · `customer["customer_unique_id"].value_counts() >= 2`
- **ผลต่องาน:** วิเคราะห์ได้แค่ระดับออเดอร์ ดูไม่ได้ว่าส่งช้าแล้วลูกค้าเลิกซื้อไหม เพราะเกือบทุกคนซื้อครั้งเดียวอยู่แล้ว
- **ไปอยู่ที่:** README > Limitations

## 2026-11-17 · ลูกค้าให้ 1 ดาวตามการเลยวันสัญญา มากกว่าตามจำนวนวันที่รอ

- **เจออะไร:** รัฐที่ส่งนานที่สุดอย่าง AM (median 25.9 วัน, n = 144) เลยวันสัญญาแค่ 2.8% และได้ 1 ดาว 6.9% ต่ำกว่าค่าทั้งประเทศ (9.7%) ส่วน AL, MA, SE เลยวันสัญญา 15–21% และได้ 1 ดาว 15–16% · ในออเดอร์ที่ส่งถึงภายใน 15 วัน ถ้าเลยวันสัญญาได้ 1 ดาว 24.4% (n = 434) เทียบกับ 6.0% (n = 69,162)
- **ทำไม:** สมมติฐานของ Om: ลูกค้าแต่ละพื้นที่มีบรรทัดฐานว่า "ช้า" ไม่เท่ากัน และวันสัญญาที่ Olist แสดงตอนสั่งคือความคาดหวังนั้น
- **หลักฐาน:** `notebooks/05_eda.ipynb` ขั้น 5 (by_state + late_rate, fast orders < 15 วัน)
- **ผลต่องาน:** เปลี่ยนข้อเสนอจาก "ส่งให้เร็วขึ้น" เป็น "ตั้งวันสัญญาให้แม่น" · ยังเป็นความสัมพันธ์ PA เป็นข้อยกเว้น (late 10.8% แต่ 1 ดาว 14.4%) และ AP, RR, AC มี n < 100
- **ไปอยู่ที่:** README > Key findings (ข้อหลัก)
